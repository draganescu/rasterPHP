# Bundled booking model Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `system/models/booking/` so a café (sittings) or a salon (appointments, with or without "with Ana") takes bookings from its own pages. Guests book, get an email at each step with a link to cancel or change, and staff run it all from a Records-recipe page with the in-page editor. A site writes no model code, and the demo café moves onto it.

**Architecture:** One bundled model, `booking`, declares five record types through `types()`: four for the setup (`bookingresource`, `bookinghours`, `bookingclosed`, `bookingservice`) and `booking` itself. These count only where a view uses `render.booking.*` or `print.booking.*`. Slot arithmetic is plain PHP over minutes of the site's wall clock. Capacity in `check()` is one SQL file, run inside the write's transaction. Two small additions to `cms_records` let the model own derived fields (`fill()`) and tell guests from staff (`writer()`). Status changes, tokens, events and emails go through `cms_records` writes and events that wait for the commit. Mail goes out after the answer, as G4 set up.

**Tech Stack:** PHP 8.1+ in Raster style (no namespaces, types, `[]`, `match`, arrow functions; tabs), RedBean, SQLite and MySQL, `cms_records`, plain-PHP tests (`test()`, `check()`, `same()`).

**Spec:** `docs/designs/booking.md` (approved; its decisions are final). Builds on `docs/plans/2026-10-18-phase1-groundwork.md` as merged in 2.2.10. Issues touched: #80, #88, #110, #125.

## Global Constraints

- STYLEGUIDE.md in full: `array()`, no type declarations, static hooks, lowercase snake_case, `/** */` header on the bundled model, `//` comments that say why.
- No new dependency. SQL lives in `system/models/booking/sql/*.sql` and runs as `database::instance('booking')->name(...)`. Records go through `cms_records` only.
- SQL takes PHP's clock as arguments (`date('Y-m-d')`, `time()`), never SQLite `date('now')` or MySQL `NOW()`.
- Problem names are written as literals (`$problems[] = 'fully_booked'`, `cms_records::refuse('too_late')`) so `lint` knows they are raised.
- The template owns every word. The model returns rows, `false`/`null`, or problem names. The page words alerts and emails.
- AGENTS.md changes go in the same commit as the behaviour. Each PR documents its own part. B4 finishes the "Bundled models: booking" section and the worked staff page.
- A new demo-visible feature gets an ID in `demo/README.md`. The next free letter is **P**.
- Each PR is its own release (2.2.11–2.2.14). Writers add the CHANGELOG section; the merger bumps `system/VERSION`.
- Every suite stays green on SQLite locally: `php tests/run.php`, `php tests/update.php`, `php tests/demo.php`, `php tests/shop.php`, `php bin/raster lint`, `RASTER_APP=demo php bin/raster lint --all-themes`. CI adds PHP 8.1, 8.4 and MySQL. Never run `tests/mutate.php`.
- `tests/run.php:222` keeps passing: a page request loads nothing from `system/tools/`. A site that doesn't use booking loads no file from `system/models/booking/`, gets no tables, and sees nothing new in `describe`, Admin or MCP.
- Anti-goals from the design are tests, not hopes:
  - no JavaScript is needed to book;
  - a GET changes nothing;
  - no token, email or phone appears in a slug, public list, log, event or the page cache;
  - the staff page keeps the in-page editor.
- Each PR branches from the previous PR's branch: `booking/b1-setup` → `booking/b2-type` → `booking/b3-guest` → `booking/b4-demo`.

## Decisions (plan's calls, where the design is silent)

1. **How check() recognises staff.** `cms_store::store_item` records its `$who` (`visitor`, `editor`, `model`) in `cms_records::$writer` while `fill()` and `check()` run, and puts back the previous value afterwards (in `finally`). `cms_records::writer()` returns it. `booking::is_staff()` is true when the writer is `editor` (the in-page editor, MCP) or `model` with `booking::$acting !== 'guest'`. The model's own guest paths (form, manage) set `booking::$acting = 'guest'` around their writes. Model code that calls `cms_records::create/update` on bookings is trusted like staff (documented).
2. **Derived fields.** A new static hook `fill($type, $after, $before)` returns values for fields the model owns. `store_item` merges them before `check()`; they are cleaned by type like any value. Booking uses it to keep `ends`, `resource` (one resource), `people` (1 when every resource has `people` 0), `changed_at` and `token_expires` right on every write, including an editor's change of `time`. `fill` joins `cms_records::$hooks` (never an action), and `lint` reports a non-static `fill()` as it does `check()`.
3. **Ends past midnight.** A booking ends by 24:00. A start whose span would end later is not a slot. An end at exactly 24:00 is stored as `00:00` and read as 1440 minutes, in `booking::minutes($t, true)` and in the SQL `CASE`.
4. **DST.** Slots are wall-clock times on the date. A start that doesn't exist (the spring gap) is dropped. The repeated autumn hour appears once. Durations are wall minutes. Notice, horizon, cutoff and link expiry use real seconds: `booking::starts_at($date, $time)` is `strtotime("$date $time")` in the site's `timezone`.
5. **A start in several hours rows.** It keeps the smallest `every`, so the default length is the shortest. Rows with `every` < 1 are refused at write time and never loop.
6. **Services.** A service is required only when the booking's resource offers at least one active service. Otherwise the booking lasts the `every` of its hours row and has no service (the café).
7. **Renamed or removed setup.** Renaming a resource's or service's `name` keeps its slug. Changing the slug or deleting the record is refused (`resource_in_use`, `service_in_use`) while an active booking dated today or later uses it. A booking whose resource slug matches no resource needs attention as `resource_inactive`.
8. **Limits by writer.**
   - `booking_max_people` applies to guests only (the design's settings table says "for guests"). `people` < 1 is refused for everyone.
   - `resource_inactive` and `service_unavailable` are refused for every writer on create or move.
   - Staff may add a booking in the past (a walk-in).
9. **Problem names beyond the design's.**
   - Booking writes: `resource_invalid` (several resources, none or an unknown one chosen), `email_invalid` (a guest with no valid email; anyone with an invalid one), `name_invalid` (empty name, so the slug never falls back to the email), `already_confirmed`, `already_declined`, `already_cancelled`, `already_booked` (same email, date, time and resource already active: a double click).
   - Setup records: `every_invalid`, `hours_invalid`, `days_invalid`, `season_invalid`, `limit_invalid`, `minutes_invalid`, `closed_invalid`, plus `resource_in_use` and `service_in_use`.
10. **Rows for templates are text.**
    - `full` is `'1'`/`'0'`, with `state` `free`/`full` for `print.+class.state`.
    - `left_people` and `left_bookings` are `''` when that limit is 0.
    - The reason: a `false` in a model's row keeps the mock-up (#125).
11. **Tokens.**
    - `bin2hex(random_bytes(32))` (64 hex characters). Each email adds its `hash('sha256', $raw)` to `token_hashes`, and the newest 20 are kept.
    - Lookup: `sql/by_token.sql` (`token_hashes LIKE ?`), then `hash_equals` over the decoded list.
    - The manage page sends `Referrer-Policy: same-origin` and posts to its own URL, so the token rides in the query string, not in a hidden field.
    - After a guest POST it redirects to `?done=cancelled` / `?done=rescheduled` without the token. A manage page with `?done=` and no token shows only that alert, not `link_invalid`.
12. **Writes the model doesn't make itself** (staff adding or moving a booking in the editor or MCP). A `cms.item_saved` listener, `booking::saved`, issues the guest's token in a second write after the commit and dispatches `booking.requested` / `booking.rescheduled` with `who` = `staff`.
    - `fill()` notes a staff move in `booking::$moved[$id]`.
    - The model's own writes set `booking::$writing`, and the listener ignores those.
    - A staff-made booking does not email `booking_new` to staff.
13. **Binding.** The listeners (`saved`, plus one `*_mail` per event) are bound in `system/config/events.php` only when `controller::model('booking')['bundled']`. A site's own `booking` model never gets them, and a site can unbind any of them in `config/the_events.php`, as with `newsletter.subscribed`.
14. **Guest changes.** A guest reschedule changes `date` and `time` only. Choosing the same slot writes nothing and sends nothing.
15. **Page cache and privacy.**
    - `slots`, `days` and `manage` call `raster_cache::skip()`: availability goes stale by the minute.
    - `agenda`, `attention` and `count` return `array()` / `'0'` unless `authentication::can('editor')`, so they are private wherever they are placed.
16. **Manage page slots.** On the manage page, `render.booking.slots('date=?date&for=manage')` takes resource, service and people from the managed booking (`booking::managed()`, resolved once per request), which doesn't count against itself.
17. **`days` limit.** It returns at most `limit` days (default 14). It scans no further than `booking_horizon` and makes two queries in all (setup and the window's bookings).
18. **No `api()`.** Booking has no `api()`. Staff use the editor and MCP; guests use forms.
19. **Lint severity.** "lint gives a notice" uses the existing `warning` severity: G1's shadow warning for a site model named `booking`, plus a new one for a site type named `booking`.
20. **Records with nothing set up.** `requires()` gets a `records` key (region => types that need at least one record). `lint` warns on `render.booking.form` when there is no `bookingresource`, and skips quietly when the database can't be reached.
21. **Protected prefixes.** The staff recipe protects `staff` and `booking_item`, never `booking`, because a prefix would lock the guest's manage page. `lint` warns when a view rendering `render.booking.manage` is protected for `editor`/`admin`.
22. **Demo seed.** *(Revised: a fresh demo must take bookings.)* `demo/seed.php` (like `shop/seed.php`: CLI only, idempotent, through `cms_records::create`) adds the setup records listed in B4 — Dining room, its sittings, the 12-25 closed day, Ana and Mihai with their hours and two services. `tests/demo.php` runs it (and may still use MCP `create_item` to check staff can make setup records). demo/README.md and the café's setup docs say to run `php demo/seed.php` after `schema --apply`; until then the form shows `not_open`.
23. **Issues.** #80: B2. #88 and #125: B4, the staff and account pages they touch. #110: avoided, not fixed (`?token=`, no route parameters).

## Review Focus

1. **The DST day in `Europe/Bucharest`** (2027-03-28 forward, 2026-10-25 back): no 03:00/03:30 slots in spring, 03:00 once in autumn, and notice counted in real minutes, so wall 04:00 is only 30 real minutes after 02:30 on the spring day. Test: B1 `the time zone across DST`.
2. **Services that overlap across slot boundaries.** A 90-minute colour at 10:00 blocks a 09:45 cut but not 09:30 or 11:30. People are counted at the busiest minute, not summed over everything that overlaps. Tests: B1 `peak counts the busiest minute, not the sum`, and B2 `capacity: a bookings limit across slot boundaries` (with the property check that `slots()` `full` equals what `check()` refuses).
3. **The last place, taken at once, on MySQL.** Writes serialise on `GET_LOCK`. The peak SQL binds repeated positional `?` (no repeated `:name`). Tables are made before the race, because a schema change commits on MySQL. Test: B2 `concurrent last place: one gets it, the rest fully_booked`.
4. **A site with its own `booking` model, or a `booking` type in another model.** The site's model wins whole. The bundled types and listeners are absent, its pages still render, and lint warns. Tests: B1 `a site booking model or type keeps the name`, and B3 `bundled listeners are not bound to a site's own booking model`.
5. **A stale manage link.** After a reschedule, the first email's link still opens the booking at its new time (its expiry moved). After a cancel or decline, or past the start, every link is `link_invalid`. A GET from a mail scanner changes nothing. Tests: B3 `guest reschedule goes back to requested; old links follow the booking`, and `expired, used and foreign links are invalid`.

  - `static function setup()` → `array('resources' => slug => row, 'hours' => rows, 'closed' => rows, 'services' => slug => row)`, read once per request. `static function forget()` clears it.
  - `static function minutes($time, $end = false)` → int from `H:i` or MySQL's `H:i:s`; with `$end`, `00:00` is 1440. `static function clock($minutes)` → `H:i` (1440 → `00:00`).
  - `static function starts_at($date, $time)` → Unix time in the site's zone.
  - `static function is_closed($date, $resource)` → bool. The closed range `date`..`until` is inclusive; a row with empty `resource` closes every resource.
  - `static function starts($date, $resource)` → `array(array('time' => 'H:i', 'every' => int), …)`, sorted and unique: the union of the starts of every applying row, minus closed days and DST-gap times. A row applies when its `resource` is empty or the slug, its `days` has the weekday or is `daily`, and the date falls in `from`/`until` (empty = always).
  - `static function offers($service, $resource)` → bool (`resources` empty = all; the service must be active).
  - `static function length($resource, $service, $every)` → minutes: the service's, else `$every`.
  - `static function peak($rows, $from, $to)` → `array('people' => int, 'bookings' => int)`: the most at any minute of `[$from, $to)` over rows with `time`, `ends` and `people` (half-open spans).
  - `static function day($date, $resource, $service = '', $people = 1, $taken = array(), $now = null)` → rows `date`, `time`, `ends`, `left_people`, `left_bookings`, `full`, `state`. Drops starts within `booking_notice` minutes of `$now` (default `time()`), dates past today + `booking_horizon` days, and spans ending after 24:00.
  - `static function options($argument)` → array from `'date=?date&resource=?resource'`: `?x` reads `$_GET['x']`, and empty values are left out.
  - Template methods (instance):
    - `slots($options = '')` → `day()` for `date`, `resource`, `service`, `people`. With one resource it is used when none is given; with several and none given, or with services offered and none given, it returns `array()`.
    - `days($options = '')` → rows `date`, `slots_free` (option `limit`, default 14).
    - `resources($options = '')` → `cms_records::listed('bookingresource', active rows)`, option `service=` keeps the ones offering it.
    - `services($options = '')` → `listed('bookingservice', active rows)`, option `resource=`.
- Settings: `booking_notice` 60 (minutes), `booking_horizon` 60 (days).
