# Spam checks and the bundled contact model Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every post form carries a signed time stamp. Any form model can ask `validation::get()->suspect()` whether a post looks like spam. The bundled public forms (newsletter, sign-up, forgot, booking, and every `cms_records::submit` form) turn suspect posts away without losing what was typed. The bundled `contact` model stores every message, keeps suspected ones aside as `spam`, and emails staff about the rest. The café's hand-written contact form moves onto it.

**Architecture:** The stamp is added by `template::index_forms()` next to `raster_hp`, signed with a site key from `util::secret()`. The page cache stores a marker in its place and `serve()` writes in a fresh stamp. The checks live in a helper class, `validation_spam` (`system/models/validation/spam.php`). It is reached through `validation::suspect()`, keeps hashed counts in two tables the validation model declares, and passes whenever a check can't run. `contact` is a bundled model like `booking`: it declares the private `contactmessage` type, a `fill()` that owns status and reasons, actions, an email listener bound in `system/config/events.php`, and the staff regions.

**Tech Stack:** PHP 8.1+ in Raster style (no namespaces, types, `[]`, `match`, arrow functions; tabs), RedBean, SQLite and MySQL, `cms_records`, plain-PHP tests (`test()`, `check()`, `same()`).

**Spec:** `docs/designs/contact.md` (approved 2026-10-19; its nine decisions are final). Builds on what booking's B1–B4 merged (`fill()`, `writer()`, `controller::uses()`, `requires()['records']`, mail after the answer). Tracking: #168 Phase 1.5.

## Global Constraints

- STYLEGUIDE.md in full: `array()`, no type declarations, static hooks, lowercase snake_case, a `/** */` header on each bundled model, `//` comments that say why.
- No new dependency. SQL lives in `system/models/<model>/sql/*.sql` and runs as `database::instance('<model>')->name(...)`. Records go through `cms_records` only.
- SQL takes PHP's clock as arguments (`date('Y-m-d H:i:s')`, `time()`), never `date('now')` or `NOW()`.
- Problem and alert names are literals (`$v->raise('try_again')`, `$problems[] = 'message_invalid'`) so `lint` knows they are raised.
- The template owns every word. Models return rows, `false`/`null`, or names.
- **No raw IP, anywhere.** Not in a table, a log line, an event payload, the page cache or an exception message. Hashes only, with the day's salt, and the salt is deleted with its counts.
- **A check that can't run passes.** Every database or key failure inside `validation_spam` is caught. It logs `log::warning('spam: …')` without the IP or the address, and that check returns no reason.
- **Nothing is mailed to an address a visitor typed.** The visitor's address only ever reaches `Reply-To`.
- AGENTS.md changes go in the same commit as the behaviour. Each PR documents its own part.
- A new demo-visible feature gets an ID in `demo/README.md`. The next free letter is **Q**.
- Each PR is its own release (the next 2.2.x when it merges; #199 may take 2.2.22 first). Writers add the CHANGELOG section; the merger bumps `system/VERSION`.
- Every suite stays green on SQLite locally: `php tests/run.php`, `php tests/update.php`, `php tests/demo.php`, `php tests/shop.php`, `php bin/raster lint`, `RASTER_APP=demo php bin/raster lint --all-themes`. CI adds PHP 8.1, 8.4, 8.5 and MySQL. Never run `tests/mutate.php`.
- `tests/run.php`'s "a page request loads nothing from `system/tools/`" keeps passing. A site that doesn't use contact loads no file from `system/models/contact/`, gets no `contactmessage` table, and sees nothing new in `describe`, Admin or MCP.
- Each PR branches from the previous one: `contact/c1-stamp` (from `master`, once #191 and this plan are merged) → `contact/c2-suspect` → `contact/c3-forms` → `contact/c4-model` → `contact/c5-demo`.

## Decisions (plan's calls, where the design is silent)

1. **The key.** `util::secret()` returns `getenv('RASTER_SECRET')` when set and non-empty. Otherwise it returns the contents of `APPBASE.'data/secret'`, making the file first: `bin2hex(random_bytes(32))`, opened with `fopen($file, 'x')` so two first requests can't write different keys (the loser reads the winner's file), then `chmod 0600`. When the file can't be made or read it returns `''`, and a stamp check that sees `''` can't run (Rule: passes, logs once per request). The value is kept in a static for the request. It is not a config setting, so `describe` never sees it.
2. **The stamp's format.** `<unix time>.<hash_hmac('sha256', 'raster_ts|'.<time>, key)>`, all 64 hex characters, compared with `hash_equals`. `validation_spam::stamp($time = null)` makes one. `validation_spam::stamp_age($value)` returns seconds since it was made, `null` for no value, or `false` for a bad signature or format.
3. **Which checks a stamp setting turns off.** `spam_min_seconds` false turns off the whole stamp check (`no_stamp`, `stamp_invalid`, `too_fast`, `stamp_old`). `spam_max_age` false turns off only `stamp_old`. `spam_per_ip`, `spam_per_email` and `spam_max_links` false each turn off their own reason. An empty `spam_blocklist` checks nothing.
4. **Where the stamp is left out:** emails (`$this->is_email`), `getenv('RASTER_EXPORT')`, and forms without an owner (no render block: nothing reads them). `raster_ts` joins `raster_form`, `raster_hp` and `csrf` in one list, `template::$internal_fields`, which replaces the three inline arrays in `system/template.php`.
5. **The cache marker.** `raster_cache::store()` replaces every `name="raster_ts" value="…"` with `value="{{raster:ts}}"` and adds `'ts' => true` to the copy's first-line JSON when it replaced any. `serve()` with `ts` reads the rest with `stream_get_contents`, does `str_replace('{{raster:ts}}', validation_spam::stamp(), …)` (one stamp for every form on the page) and echoes. Without `ts` it streams with `fpassthru` as now. A 304 is answered as today.
6. **`suspect($fields = null)`** is on `validation` and delegates to `validation_spam::reasons($owner, $fields)`. It is cached per owner for the request, so calling it twice counts once. `$fields` null means every field of `template::instance()->forms[$owner]` present in `$_POST`. `array()` means no text check (no links, no blocklist), which is what the bundled forms other than contact pass. It returns `array()` when `authentication::can('editor')`, without counting, and also outside a submitted form (`!$this->submitted($owner)`).
7. **Reason order** is the design's table: `no_stamp`, `stamp_invalid`, `too_fast`, `stamp_old`, `too_many_from_ip`, `too_many_from_email`, `too_many_links`, `blocked`. At most one stamp reason. Every check runs, so a post can carry several reasons.
8. **Counting happens inside `reasons()`, before the limits are compared.** The post being checked is counted (one `formhit` row each for `ip` and `email`), and the limit is exceeded when the count in the last hour, this post included, is above the setting. So the 6th post from one IP within the hour is the first `too_many_from_ip` (with `spam_per_ip` 5). A post without a valid email counts only by IP.
9. **Hashing.** `validation_spam::hash($value)` = `hash('sha256', $salt.$value)`. IPv4 is used whole. IPv6 uses its first 64 bits: `inet_pton`, the first 8 bytes, `bin2hex`. An address that isn't an IP (a test's `REMOTE_ADDR` missing) hashes `'unknown'`. Email: `strtolower(trim())`.
10. **The salt.** `formsalt` has one row (`day`, `salt`, `proxied`). `validation_spam::salt()` reads it. When `day !== date('Y-m-d')` (the site's `timezone`), inside `cms_records::transaction()` it deletes every `formhit` row and the old salt row, then stores a new one (`bin2hex(random_bytes(32))`). The transaction makes two requests at midnight agree on one salt (the second sees the new row after the lock). Expiry: each count insert first deletes rows of that form older than an hour (`sql/expire.sql`).
11. **The client IP.** `validation_spam::client_ip()` uses `REMOTE_ADDR` unless it matches `trusted_proxies` (exact or CIDR, v4 and v6, via `validation_spam::in_range($ip, $range)`). Then it reads `client_ip_header`, default `X-Forwarded-For`, from `$_SERVER['HTTP_'.strtoupper(str_replace('-', '_', $header))]`. For a list it takes the last entry that isn't itself trusted. When that header is missing or not an IP, it keeps `REMOTE_ADDR`.
12. **`doctor` and the proxy.** When `REMOTE_ADDR` is private or reserved (`!filter_var($ip, FILTER_VALIDATE_IP, FILTER_FLAG_NO_PRIV_RANGE | FILTER_FLAG_NO_RES_RANGE)`, loopback included) and `trusted_proxies` is empty, `reasons()` sets today's `formsalt.proxied` to 1. `doctor` warns when today's row has `proxied` 1: "Posts arrive from a private address and `trusted_proxies` is empty, so every visitor shares one spam count". It says nothing when the table doesn't exist. `doctor` runs in the CLI, so it can only learn this from the database.
13. **Links**: `preg_match_all('~https?://|www\.|\[url=~i')` over the checked fields joined with newlines. Too many is `count > spam_max_links`.
14. **Blocklist**: an entry without a dot is a word, matched by `/(?<![\p{L}\p{N}])<quoted>(?![\p{L}\p{N}])/iu`. An entry with a dot is a domain. It matches the email's domain, or a host in the text (`[a-z0-9.-]+` after `://` or `www.`, or the email domain), when the host is the entry or ends with `.`.entry.
15. **What the bundled forms do with reasons.** `validation::hold($reasons)` raises `slow_down` when any reason starts with `too_many_from_`, else `try_again`, and returns `template::instance()->form_state()`. Callers use it as `if ($reasons = $v->suspect(array())) return $v->hold($reasons);`:
    - `newsletter::signup()`, `authentication::register()`, `cms_records::submit()` (and so `booking::form()`), right after `valid()`.
    - `authentication::forgot()` keeps only the two limit reasons (`array_intersect`), and when there are any it does `util::done('reset_sent')` without looking up the user.
    - `cms_records::submit()` checks only when `$info['create']` is `visitor` or `member` and the type doesn't say `'spam' => false` (a new key in `cms_records::types()` normalisation, default true). It checks before `may_create()` refuses, so a bot doesn't learn which types need a login.
16. **lint's `try_again` warning.** `raster_inspector` warns once per view that has a region in `validation_spam::$checked_regions` (`render.newsletter.signup`, `render.authentication.register`, `render.booking.form`, and from C4 `render.contact.form`) and no `print.validation.alert('try_again')`, and the same for `slow_down`. Message: "<view>: <region> can turn a post away as spam; add print.validation.alert('try_again') and print.validation.alert('slow_down') so the person knows to send it again". Site forms built on `cms_records::submit` aren't covered, because lint can't see which method calls it. That gap is accepted.
17. **Tests post as browsers do.** Each suite's `http()` adds `raster_ts` to an array body that has `raster_form` and no `raster_ts`, as `stamp_for_tests(60)`: a stamp made 60 seconds ago with `RASTER_SECRET=test-secret`, which each suite `putenv`s before its servers start. The demo's main server gets a knob, `CAFE_SPAM_LIMITS=off`, which sets `spam_per_ip` and `spam_per_email` to false, because the suite posts many forms from 127.0.0.1. The spam tests start their own server without it. In `tests/run.php` a test that posts one form more than 5 times clears `formhit` (`test_pdo($db)->exec('DELETE FROM formhit')`).
18. **`contactmessage` fields, in this order:** `title` (readonly; `fill()` sets `date('Y-m-d H:i')` on create, so the slug is `2026-10-18-1432` and never the email), `name`, `email`, `phone`, `subject`, `message`, `page` (readonly), `status` (readonly, default `new`), `spam` (readonly). Type: `create` visitor, `public` false, no `owner`, no `staff_add`, `'spam' => false` (the model runs its own checks), actions `done`, `spam`, `not_spam`, all `editor`.
19. **How the model's own checks reach `fill()`.** `contact::form()` runs `suspect(array('name', 'subject', 'message'))` (the email's domain is checked by the blocklist either way), puts the reasons in `contact::$reasons`, and calls `cms_records::submit('contactmessage', false)` inside `contact::$writing = true`. `fill()` on create sets `status` to `spam` when `contact::$reasons` is non-empty, `spam` to `implode(',', $reasons)`, and `page` to `'/'.ltrim(strtok((string)config::get('uri_string'), '?'), '/')`. Writes from staff (the editor, MCP) on create keep `status` `new` and `page` `''`.
20. **A double click.** In `form()`, before `submit`, `sql/recent.sql` (`SELECT id FROM contactmessagedata WHERE email = ? AND message = ? AND created_at >= ?`, 10 minutes back) finds a twin. Then nothing is stored and it answers `util::done('sent')`. The query is skipped when the table doesn't exist yet.
21. **Spam retention.** After a store, `sql/expire_spam.sql` deletes `status = 'spam' AND created_at < ?` (now minus `contact_spam_days` days). It is skipped when `contact_spam_days` is false.
22. **Events and mail.** `form()` dispatches, after the store, `contact.received` (status `new`) or `contact.flagged` (status `spam`) with `contact::payload($record, 'visitor')`: every field but `title`, plus `who`. `not_spam` dispatches `contact.received` with `who` `staff`. `system/config/events.php` binds `contact.received` → `contact::staff_mail` only when `controller::model('contact')['bundled'] && controller::uses('contact')`. `staff_mail` returns at once when `who` is `staff`, so `not_spam` mails nothing.
23. **`Reply-To`.** `contact::reply_to($name, $email)` → `'"'.str_replace(array('"', '<', '>', ','), '', $name).'" <'.$email.'>'`, or just the email when the name is empty. It is passed as `array('Reply-To' => …)` to `mail::send_view()`, which runs it through `named()` and `clean_header()`. A unit test asserts the stored mail file has exactly one `Reply-To:` line and no `Bcc:`.
24. **Contact problem names** (from `check()`, all writers): `name_invalid`, `email_invalid`, `phone_invalid`, `subject_invalid` (a control character, `/[\x00-\x1F\x7F]/`, or over 200 characters; `email` also fails `FILTER_VALIDATE_EMAIL`, is over 254, or is empty), `message_invalid` (empty, or over `contact_max_length` characters by `mb_strlen`). Status changes: `done` from `spam` is refused `not_done_spam` (mark it not spam first), and `not_spam` on a message that isn't spam is refused `not_spam_invalid`.
25. **Staff regions.** `render.contact.messages($options = 'status=new&order=-created_at')` → `cms_records::listed('contactmessage', cms_records::find('contactmessage', $options))`, `array()` unless `authentication::can('editor')`. `print.contact.count($options = 'status=new')` → `(string)count(find(...))` for editors, `''` otherwise. Both call `raster_cache::skip()`.
26. **`requires()` and `describe`.** `contact::requires()`: `emails` `render.contact.form` ⇒ `array('_email/contact_received')`; `settings` `contact_staff_email`, `contact_staff_page`, `contact_max_length`, `contact_spam_days`. The eight spam settings (`spam_min_seconds`, `spam_max_age`, `spam_per_ip`, `spam_per_email`, `spam_max_links`, `spam_blocklist`, `trusted_proxies`, `client_ip_header`) go in `describe::$settings` (`system/tools/describe.php:24`), since every site has the checks whether or not its views use `validation.*`.
27. **lint for the staff page.** The existing "Visitors make '<type>' records with a form, but no view lists them" warning (`system/tools/inspector.php:1272`) already covers `contactmessage`. `render.contact.messages` must count as listing it: extend `$this->listed($name)` to accept a model region that the model declares lists the type, through a new `requires()` key, `'lists' => array('contactmessage' => array('render.contact.messages'))`. Also add a warning when a view rendering `render.contact.messages` isn't matched by `protected` for `editor` or `admin`: "<view> lists contact messages but isn't protected for editors". It uses the same pattern matching as `authentication`'s protected check.
28. **Upgrade step.** None. A site's own `contact` model keeps working, shadowing the bundled one. The CHANGELOG notes say how to move.

## Review Focus

1. **A proxy in front, unconfigured.** On raster-builder and Fly every request comes from one private address. With `trusted_proxies` empty, every visitor shares one count, so the 6th visitor of the hour gets `slow_down` on the newsletter. Expected: the doctor warning appears, and with `trusted_proxies` set the visitors count apart. Test: C2 `a trusted proxy's header is read, an untrusted one ignored`, and C2 `doctor warns when posts come from a private address`.
2. **Two forms on one cached page.** The footer's newsletter and the contact form share one cached copy. Expected: both get the same fresh stamp at `serve()`, each validates, and the copy on disk holds only the marker. Test: C1 `a cached page with two forms serves fresh stamps to both`.
3. **A frozen production database before `schema --apply`.** There is no `formhit` table, and every form must still work. Expected: limits pass with one warning per request, contact still stores its message if `contactmessagedata` exists, and the stamp still works (it needs no table). Test: C2 `checks that can't run pass and log`, with a frozen database.
4. **A newline in the visitor's name reaching a header.** `name = "Ana\r\nBcc: x@evil.test"`. Expected: `name_invalid`, nothing stored, nothing mailed. With a name `Ana "The Boss" <x>`, the mail has one `Reply-To` and the quotes and brackets are dropped. Test: C4 `header injection is refused and Reply-To is one header`.
5. **Editors testing their own form.** An editor's post within 1 second. Expected: no reasons, stored as `new`, mailed, and no `formhit` row. Test: C2 `editors are never flagged or counted`.
